# Security and scope

Use ScopeGuard only within an agreed testing scope. GET requests may still have application side effects. Start with a single page when unsure about crawler paths.

Reports are sensitive artifacts. Query and cookie values are omitted, but URL paths, cookie names, selected response-header evidence, and target identities remain. Do not commit real reports or credentials.

If you find a vulnerability in the tool itself, use the repository's private vulnerability reporting channel if the repository owner has enabled one. Do not post credentials, real target reports, or exploit details in a public issue. Repository owners should enable private vulnerability reporting before accepting disclosures.

Configuration candidates must be verified in context. This tool neither confirms authenticated exploitability nor performs a full penetration test.
